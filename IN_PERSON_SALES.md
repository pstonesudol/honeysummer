# In-person sales: Stripe Dashboard Tap to Pay

Honey Summer can take contactless payments at markets using the **Stripe Dashboard mobile app** on a compatible phone. This is Stripe's no-code Tap to Pay flow: it does not require a Terminal SDK, a card reader, or changes to the Honey Summer checkout. Isabella must set it up on her own device and Stripe account before using it for live sales.

## Set up before the first market

**Phase ownership:** Phase 7 owns the guide, device eligibility and Isabella's practice/stock-recording rehearsal. Phase 12 owns live account/device activation and the approved controlled charge/refund/stock verification, tracked in [`backend/PRODUCTION_READINESS.md`](backend/PRODUCTION_READINESS.md). Neither is assumed complete.

1. Activate the Honey Summer Stripe account for live payments. Install the [Stripe Dashboard app for iPhone](https://apps.apple.com/app/apple-store/id978516833) or [Android](https://play.google.com/store/apps/details?id=com.stripe.android.dashboard) and sign in to the **correct Honey Summer account**, not a personal or test account. Enable two-factor authentication and verify the phone number. The Stripe user must have permission to accept payments (View-only and Support specialist roles cannot).
2. Check that the device and location are supported. In the US, Stripe supports Tap to Pay in the Dashboard app on iPhone and Android. iPhone requires an **iPhone XS or later**, a passcode, an iCloud sign-in, and a supported current iOS version. Android requires a [supported NFC device](https://docs.stripe.com/terminal/payments/setup-reader/tap-to-pay.md?platform=android#supported-devices). Enable NFC where applicable, allow location access, update the Dashboard app and OS, and make sure the phone has connectivity and sufficient battery. Check [Stripe's current requirements](https://docs.stripe.com/no-code/tap-to-pay) before the event; device and region support can change.
3. Check the [current Stripe Terminal/Tap to Pay pricing](https://stripe.com/pricing#terminal), refund policy, and any applicable tax/receipt obligations. Decide how to calculate the full amount **before** charging; the Dashboard app's amount-only charge is not a Honey Summer itemized cart or tax calculator.
4. Practice the flow on the actual device before taking live customers. Use the app's test mode if available to learn the screens, then switch back to the intended **live** account/mode and confirm it before the first real sale. A sandbox success is not a live-payment verification. Do not make an unnecessary real charge just to test without an agreed refund procedure.

## At the point of sale

1. Confirm the items and quantities, calculate the total (including any tax that applies), and check that enough unreserved inventory is available in Honey Summer if the items are listed online.
2. In the Stripe Dashboard app, tap **+ → Charge a card or send an invoice**, enter the amount, and select **Tap to Pay**. Follow the on-screen instructions and ask the customer to tap a contactless card or NFC wallet. Wait for Stripe's **payment confirmation**; an attempted tap is not proof of payment. Offer the Stripe receipt if appropriate and retain the Stripe payment/receipt reference for your records. Do not record a sale for a declined or abandoned payment.
3. For each online-listed item sold, open `/admin/flowers`, select the listing, then **View inventory history and adjust stock**. Choose **In-person sale (-)**, enter the *positive* number of listing units (stems or bunches, matching the listing), and put the Stripe payment/receipt reference and brief market-sale details in **Reason / sale reference**. Record each listing separately. Check the updated available quantity and movement history. The in-person sale action reduces *available* stock; it does not change an existing online reservation. Never edit stock directly in the database.
4. Match the day's Stripe Tap to Pay transactions against the market-sale movements and other sales records. If an item is not tracked by a Honey Summer listing, keep an external sale record instead of adjusting an unrelated listing. If you miss an adjustment, record it promptly with the original payment reference; don't submit the same movement twice.

## Important boundaries and exceptions

- A Dashboard Tap to Pay payment is **not** a Honey Summer retail/wholesale Checkout session or order. It will not appear in `/admin/orders`, send Honey Summer order confirmation emails, or be reconciled by `app.reconcile`. The Checkout webhook handles website payments only. **Do not also put the same sale through website checkout**; that would charge or deduct inventory twice.
- If the Stripe charge succeeds but stock adjustment fails (for example, stock is already reserved or available is insufficient), **do not force a negative balance**. Keep the payment reference, investigate the discrepancy and arrange fulfillment or a refund with the customer. Correct stock through the audited admin action only after checking physical stock and outstanding reservations.
- For a refund, locate the payment in the Stripe Dashboard and follow Stripe's refund flow. A Stripe refund does **not** restore Honey Summer stock. Only return usable physical goods to available stock with an audited **Restock (+)** entry (including the original payment/refund reference); otherwise leave inventory as sold. Do not treat a refund as an online-order refund or run a second in-person sale movement.
- If Tap to Pay is unavailable, stop and choose a supported fallback (for example, Stripe's manual card entry or a payment link). Check the different fees and payment-confirmation behavior before handing over goods. Never write down or store customers' card details in Honey Summer.

Phase 9 delivered a fuller manual-order and payment-recording workspace; see [`backend/OWNER_OPERATIONS.md`](backend/OWNER_OPERATIONS.md). Dashboard payments still do not import automatically. Use one documented recording path for each sale; do not deduct stock again if that sale was already recorded through a stock-aware manual order.
